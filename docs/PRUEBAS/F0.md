# Pruebas de la Fase 0 — Base

Qué hay en esta fase: el proyecto, las dos salidas (web instalable y `waterpolo.html`), el conversor
de la hoja, los datos provisionales, la pantalla **Datos del juego**, los ajustes, la capa de
depuración, la calidad adaptativa y la pantalla de "gira el móvil". **Todavía no se juega**: el
agua con los gorros de la portada es la escena de prueba de rendimiento.

Marca cada punto con ✅ o ❌ y apunta lo que veas raro.

## 1. En el PC, sin publicar nada

Desde la carpeta del proyecto:

| # | Haz esto | Tiene que pasar |
|---|---|---|
| 1.1 | `npm run dev` y abre la dirección que sale | Portada con el logotipo **WATERPOLO IRUÑA STARS 26-27**, vuestro escudo y agua en movimiento con gorros numerados. |✅
| 1.2 | Pulsa una tecla | Menú. Los tres modos salen como "Próximamente". |✅
| 1.3 | **Extras → Datos del juego** | Resumen: 19 jugadores reales y 1 provisional; 0 equipos, 0 árbitros y 0 frases reales. |✅
| 1.4 | Pestaña **Nuestro equipo** | 20 cromos: vuestras 19 caras (el 19 con silueta) y un portero "PROVISIONAL". |✅

| 1.6 | **Ajustes** → cambia algo, recarga la página | El cambio sigue ahí. |✅
| 1.7 | Pulsa `F3` (o `º`) | Panel de depuración con fps y calidad. Pulsa **×40**: los fps bajan y, en "auto", la calidad pasa sola a media o baja. |✅
| 1.8 | `npm run build` y doble clic en `dist/waterpolo.html` | Se abre y funciona igual, sin servidor. Prueba también con el wifi apagado. |✅
| 1.9 | `npm test` | Todos los tests en verde. |✅

## 2. La hoja de datos

| # | Haz esto | Tiene que pasar |
|---|---|---|
| 2.1 | En `datos/plantilla.ods`, pon barras a un jugador y guarda. `npm run datos` | Su cromo muestra las barras y deja de decir "barras sin rellenar". |
| 2.2 | Pon `Velocidad = 12` a alguien. `npm run datos` | El informe dice *"Jugadores, fila N: Velocidad = 12 no es válida; se usa 5"* y el juego sigue funcionando. |
| 2.3 | Añade en **Equipos** una fila con ID `sestao`, nombre, siglas, nivel y estilo | Aparece como **Real** en Datos del juego → Rivales, con su escudo, y entra en la Copa. |
| 2.4 | Pon `Activo = No` a un jugador | Desaparece del equipo. |
| 2.5 | Renombra la hoja (como si no existiera) y `npm run datos` | Todo provisional: 13 jugadores inventados, y el juego arranca igual. Vuelve a dejarla como estaba. |
| 2.6 | Abre `data/INFORME_DATOS.md` | Dice lo mismo que la pantalla Datos del juego, en texto. |

IDs propuestos para los escudos que ya tienes: `nautica-portugalete`, `sestao`, `urbat`,
`urgara-txingudi`, `donosti`. El escudo y la foto se buscan solos por ese ID.

## 3. Publicación (cuando demos el paso)

Antes de subir nada a GitHub hay que **vaciar la columna Nombre** de la pestaña Jugadores: el
repositorio es público y el historial no se puede borrar después.

| # | Haz esto | Tiene que pasar |
|---|---|---|
| 3.1 | Sube un cambio a `main` | En la pestaña *Actions* de GitHub corre "Publicar" y en unos minutos la web está actualizada. |

| 3.3 | Mira el resumen de la ejecución en *Actions* | Sale el informe de datos. |
